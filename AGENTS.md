# Инструкции для Codex (проект feSpamBlock)

Главное: отвечать по-русски; сервер не трогать вообще (это делает Claude); не открывать любые `.env`
и `*.db`; не печатать токены; `git push` не делать; работать только в этой папке (ветка `codex-r1`).

## Проект
Сервис продажи ботов обратной связи: главный бот (`main.py`, `handlers.py`) и купленные боты
(`purchased_bot.py`, `forum_support.py`). pyTelegramBotAPI (telebot), SQLite (`database.py`),
оплата — `payments.py`, клавиатуры — `keyboards.py`. Весь текст бота — русский.

## Тесты
- Лежат в `tests/`, запуск: `python tests/<имя>.py`. Все сразу: по очереди каждый файл.
- Тест реально запускает код бота (как `tests/smoke.py`: временная `DATA_DIR`, подменённые методы
  Telegram API). Поиск по исходникам тестом не считается.
- Каждая проверка печатает `[OK]` или `[FAIL]`; последняя строка — `ИТОГО: N OK, M FAIL`;
  при любом FAIL код выхода не 0.
- Новый тест должен падать без исправления и проходить с ним. Существующие тесты не ослаблять.

## Поиск ошибок
Находки строками: `P1|P2|P3 файл:строка — сценарий -> последствие`. Только то, что реально
воспроизводится на этом коде; стиль и пожелания не писать.

## Чем заканчивать задачу
Список изменённых файлов и по строке, что сделано. Коммит не делать (песочница не даёт писать в `.git`) —
изменения оставить в рабочей папке, их проверит и закоммитит Claude.
