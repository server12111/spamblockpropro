# feSpamBlock — Claude Code Guidelines

## Как мы работаем: Claude управляет, Codex делает

### Роли
- Claude — руководитель: разбирается в задаче, ставит задачи Codex, проверяет результат, прогоняет
  проверки, отчитывается владельцу. Сам код не пишет, кроме правок в пару строк или случаев, когда
  Codex дважды не справился.
- Codex — исполнитель: пишет и исправляет код, пишет тесты, ищет ошибки.
- Владелец — принимает решения по функциям, текстам и установке на сервер.

### Как ставить задачу Codex
- Задача — файл `C:\Users\Sierafim\fespamblock-work\tasks\<имя>.md`, запуск:
  `bash C:/Users/Sierafim/fespamblock-work/run_codex.sh <имя>` (ответ — `tasks/<имя>.out.md`, журнал — `.log`).
  Внутри: `codex exec --sandbox workspace-write --skip-git-repo-check --ephemeral -o <ответ> - < <задача>`.
- В задаче: что не так или что сделать, где это в коде, какое поведение нужно, что менять нельзя,
  какой тест написать (реально запускает код, без поиска по исходникам), чем закончить — список
  изменённых файлов и по строке, что сделано.
- Codex работает только в копии `C:\Users\Sierafim\fespamblock-work\work` (ветка `codex-r1`, без `.env`),
  не в основной папке. Правила для него — `AGENTS.md`.

### Цикл
1. Поиск ошибок: Codex читает код частями и пишет находки строками
   `P1|P2|P3 файл:строка — сценарий -> последствие`.
2. Отбросить ложные находки и то, что сделано по решению владельца; сообщить владельцу: сколько найдено и какие.
3. Исправление: находки — Codex, каждая с тестом.
4. Смотреть `git diff --stat` и коротко сам дифф. Целые файлы не читать.
5. Прогнать все тесты. Что упало — снова Codex (разобрать, где ошибается код, а где тест; тест не ослаблять).
6. Повторять, пока проверка не чистая. Потом сказать владельцу «готово».

### Правила
- Владельцу писать только на русском, коротко: что сделано, что нашлось, что нужно от него.
- На сервер ничего не ставить и в боевую базу не писать без «да» владельца. Перед установкой — копия и способ отката.
- Codex упёрся в лимит или вылетел из аккаунта (`run_codex.sh` печатает `CODEX LIMIT` / `CODEX AUTH`) —
  сразу написать владельцу «смени аккаунт Codex», не ждать вопроса.
- Экономить токены Claude: не перечитывать большие файлы, не делать лишних прогонов, тяжёлую работу отдавать Codex.
- Решения на годы: чинить причину, а не латать симптом. Одна и та же ошибка во многих местах —
  одно общее правило вместо десятка заплаток.
- За тексты и кнопки для пользователей отвечает Claude: после Codex самому посмотреть, как это выглядит,
  и показать владельцу.

## Где что лежит
- **Эта папка — основная** (ветка `main`, origin — GitHub). `.env` здесь не коммитится.
- `C:\Users\Sierafim\fespamblock-work\work` — копия для Codex и прогона проверок. Синхронизация через git:
  - перед проверкой/Codex: `bash C:/Users/Sierafim/fespamblock-work/sync_from_main.sh`
  - забрать правки Codex сюда: `git pull --ff-only C:/Users/Sierafim/fespamblock-work/work codex-r1`
- Полная проверка: `bash C:/Users/Sierafim/fespamblock-work/verify_all.sh` (все `tests/*.py` в `work/`;
  с аргументом — в указанной папке), итог `TOTAL FAILURES: 0`.
- Codex коммитить не может (песочница закрывает `.git`): после его работы Claude смотрит дифф, гоняет
  `verify_all.sh`, коммитит в `work/` сам и забирает в `main`.
- Вторая копия `C:/Users/Sierafim/fespamblock-work/review` — для параллельного поиска ошибок
  (`CODEX_DIR=review bash run_codex.sh <имя>`), чтобы не мешать правкам в `work/`.

## Запуск бота локально
```bash
python main.py
```
Без `WEBHOOK_URL` — long polling; с ним — webhook (Flask, порт `WEBHOOK_PORT`), при сбое откат в polling.

## Стек
- **pyTelegramBotAPI (telebot)**, синхронный, потоки; **Flask** — webhook; **SQLite** (`database.py`, папка `DATA_DIR`).
- `main.py` — запуск главного и купленных ботов; `handlers.py` — главный бот; `purchased_bot.py` — купленный бот;
  `forum_support.py` — поддержка через темы форума; `payments.py` — CryptoBot/TON; `keyboards.py` — кнопки и premium emoji.

## Тексты бота
- Весь текст — **русский**.
- Последнее предложение абзаца/сообщения — без точки в конце.
- Тексты говорят, что функция делает и что нажать, а не как она устроена (чтобы не копировали).

## Сервер
- Бот стоит на стороннем сервере, доступа к нему нет ни у владельца, ни у Claude. Установку Claude не делает:
  результат — проверенный код в `main`, дальше его передаёт владелец.
